# Silence admin panel

The admin panel of [Silence](https://github.com/IISSI-US/silence-py) 3: a web app that
administers a Silence project through its admin API (`/_silence/v1`, see
`docs/admin-api.md` in Silence). Plain HTML, CSS and JavaScript modules, with
[UIkit](https://getuikit.com) (copied in `admin/vendor/uikit/`, MIT, no CDN) and its own
stylesheet (`admin/css/admin.css`, `sa-` prefix); no framework, no build.

It does not use ez-ui on purpose: ez-ui is what the students use (and customize) in their
own web apps, so the panel looks clearly different and gives them no ez-ui code.

## How it reaches the projects

`silence new` copies the `admin/` folder of this repo into the new project (unless
`--no-admin` is given), and `silence admin update` replaces it with the latest version.
Silence serves the project's `admin/` folder at `/admin/`. Only `admin/` is copied: the rest
of this repo is for developing it.

`admin/panel.json` has the version of the panel and the version of the admin API that it
needs (`api`); Silence warns when they do not match.

## Structure

- `admin/index.html`: the layout (sidebar, breadcrumb, page); no modal windows.
- `admin/js/main.js`: the hash router (`#/endpoints/edit/<file>/<name>`…), the breadcrumb bar
  (fixed at the top, with the project highlighted at its beginning and the Back button at its
  other end, only in second-level pages), and the state of the project. The panel does not watch
  the project: it reads its state when a page is shown and after each action (a change made with
  an editor is seen on the next page).
- `admin/js/lib/`: what the pages share, by concern.
  - `html.js`: ``html`...` `` escapes every value that it interpolates (safe by default), and the
    shared markup (tabs, switches, icon buttons, badges, options).
  - `api.js`: the client of Silence's admin API; `files.js`: the files of the project through its
    file API (read, changed and written whole, with their version); `activity.js`: what each
    action means for the activity; `student-api.js`: the student's API and the session the panel
    acts as.
  - `log.js`: the activity (the log of requests that Silence writes and the panel's own entries);
    `requestlog.js`: the lines of that log and their statistics.
  - `ui.js`: notifications, confirmations with a second click, the "being edited" mark;
    `forms.js`: reading forms.
  - `testing.js`: the unit tests (their definition, how a response is checked, the order in which
    they run) and `runner.js`: running them against the student's API.
- `admin/js/components/`: the grid of every list (`table.js`, sortable and with filters), the
  fields of a request (`request-form.js`) and the lists that the student orders (`ordered-list.js`).
- `admin/js/pages/`: one module per section (`render`, `crumbs`, `parent`, `leave`); the
  sections with tabs have one hash per tab.

Behaviour worth knowing:

- Endpoints: all in one grid (the Source column says whether each one is autogenerated or
  custom). Who can call each one is changed in the grid and saved at once, as in silence-dev4:
  Auth (a switch), Roles (a combo) and Owner (the column with the id of the owner; roles or an
  owner, not both). Changing an autogenerated one makes it custom (a copy in the custom file of
  its table, which replaces it), where its SQL can be edited; deleting a custom one (endpoint or
  test) brings back the autogenerated one, if any.
- Tests, in Endpoints: each endpoint has a Tests column (how many, and how they went) that opens
  its tests under its row: the generated ones (Silence computes them from the endpoints; they are
  not edited) and the custom ones (`tests/<table>.json`, e.g., for the business rules). "Run all
  tests" (and "Run its tests") creates the database again first with `database.scripts`, if
  there are scripts, and runs them against the student's API in the order GET, POST, PUT,
  DELETE. A generated test that fails offers a custom test from it, which expects what the API
  answered. The tests that are not of an endpoint (login, register) are listed apart. A test is
  edited as a form (`components/request-form.js`: the endpoint, its params, the user, the status
  and a part of the message); the JSON is only shown.
- Logs: the activity (the requests to the student's app, from the log that Silence writes in
  `admin/logs/requests.log`, and what the panel does, with the failures highlighted, a link from
  each line to where it happened and a run of tests in one line), with filters, and its
  statistics (the student's API, the web app and Silence's API), each route or file linked to its
  requests. "Clear the log" deletes the log and the panel's entries.

## Tests

The modules without DOM (`lib/html.js`, `lib/testing.js`, `lib/activity.js`, `lib/forms.js`,
`lib/requestlog.js`)
have tests that run with Node, without dependencies: `node --test panel-tests/*.test.mjs`.

## Development

This repo is also a small Silence project (`silence.json`, `sql/`), so the panel can be
developed in place:

```
mariadb -u iissi_user -p -e "CREATE DATABASE silence_panel_db"
mariadb -u iissi_user -p silence_panel_db < sql/create_tables.sql   # and the other scripts of sql/
silence run          # serves admin/ at http://127.0.0.1:8080/admin/
```

The database is the one of the CI of Silence (departments and employees; the passwords are
the part of the email before the `@`). The changes in `admin/` are seen when reloading the
page. What the panel saves meanwhile (`admin/data/`) is not versioned here.

To try `silence new` with a local copy of this repo (and of the templates) instead of
GitHub, set `SILENCE_SOURCES` to the folder that contains them.
