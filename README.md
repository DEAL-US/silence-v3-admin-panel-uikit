# Silence admin panel

The admin panel of [Silence](https://github.com/IISSI-US/silence-py) 3: a web app that
administers a Silence project through its admin API (`/_silence/v1`, see
`docs/admin-api.md` in Silence). Plain HTML, CSS and JavaScript modules, with
[UIkit](https://getuikit.com) (copied in `admin/vendor/uikit/`, MIT, no CDN) and its own
stylesheet (`admin/css/admin.css`, `sa-` prefix); no framework, no build.

It does not use ez-ui on purpose: ez-ui is what the students use (and customize) in their
own web apps, so the panel looks clearly different and gives them no ez-ui code.

## How it reaches the projects

`silence new` copies the `admin/` folder of this repo into the new project (unless
`--no-admin` is given), and `silence admin update` replaces it with the latest version.
Silence serves the project's `admin/` folder at `/admin/`. Only `admin/` is copied: the rest
of this repo is for developing it.

`admin/panel.json` has the version of the panel and the version of the admin API that it
needs (`api`); Silence warns when they do not match.

## Structure

- `admin/index.html`: the layout (sidebar, breadcrumbs, page, console); no modal windows.
- `admin/js/main.js`: the hash router (`#/tests/composite/edit/<name>`…), the breadcrumbs,
  the Back button (only in second-level pages: editors, try, password), the watch of the
  project's `revision` and the changes of its state for the console.
- `admin/js/pages/`: one module per section (`render`, `crumbs` and `parent`). The sections
  with tabs (Database, Endpoints, Tests, Statistics) have one hash per tab.
- `admin/js/components/table.js`: the grid of every list, sortable by column and with a
  filter under each header.
- `admin/js/components/console.js`: the console at the bottom with all the activity of the
  panel: its requests to the student's API (trying an endpoint, tests), its actions on Silence
  (testing and saving the connection, linking the users table, saving an endpoint, opening a
  session as a user…) and the changes in the project (database connected or lost, files
  changed outside the panel, errors), with the errors highlighted; kept in `sessionStorage`.
- Overview, in tabs: getting started (the steps, the problems, the app) and the settings of
  `silence.json` (login and passwords, server, advanced: database scripts, sessions, JS API,
  debug); only the values that change are saved.
- Database, in tabs: connection, tables and views, users table (its columns) and users
  (password of each one, act as);
  the tabs that need the database are disabled while the connection fails or is being changed,
  and Users until the users table is linked.
- Endpoints: all in one grid (the Source column says whether each one is autogenerated or custom).
  Who can call each one is changed in the grid and saved at once, as in silence-dev4:
  Auth (a switch), Roles (a combo) and Owner (the column with the id of the owner; an endpoint
  has roles or an owner, not both). Changing an autogenerated one moves it to custom, where its
  SQL can be edited; deleting a custom one serves the autogenerated one again, if there is one
  (the same with the tests).
- Tests: Silence generates and keeps the unit tests, but does not run them. The panel runs
  them against the student's API (in the order GET, POST, PUT, DELETE), so they change the
  database: "Reload the database" (also in Database) creates it again with the scripts of
  `database.scripts`. The unit tests are in one grid (with a Source column).
- Trying an endpoint: the user is chosen there (a session without password), and a GET of the
  same table proposes real values for the params and the body.
- Empty sections say the next step (e.g., generate the endpoints); the console can show only
  the failures, and each line links to its endpoint, test or section. Composite tests (sequences of unit tests, by name) belong only to the panel: it
  saves them through the admin API (`/panel-data/composite_tests`, that is, the project's
  `admin/data/composite_tests.json`; versioning it is the student's decision).

## Development

This repo is also a small Silence project (`silence.json`, `sql/`), so the panel can be
developed in place:

```
mariadb -u iissi_user -p -e "CREATE DATABASE silence_panel_db"
mariadb -u iissi_user -p silence_panel_db < sql/create_tables.sql   # and the other scripts of sql/
silence run          # serves admin/ at http://127.0.0.1:8080/admin/
```

The database is the one of the CI of Silence (departments and employees; the passwords are
the part of the email before the `@`). The changes in `admin/` are seen when reloading the
page. What the panel saves meanwhile (`admin/data/`) is not versioned here.

To try `silence new` with a local copy of this repo (and of the templates) instead of
GitHub, set `SILENCE_SOURCES` to the folder that contains them.
